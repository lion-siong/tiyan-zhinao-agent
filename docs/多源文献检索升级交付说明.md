## 一、故障原因分析

### 1.1 复现到的现象

文献研究页面出现两类报错，且最终「真实元数据数量为 0」，综述与研究现状模块没有真实论文支撑：

1. **Semantic Scholar 请求过于频繁（HTTP 429）**：匿名调用受服务商额度限制，触发限流；提示可在 `.env` 配置 `SEMANTIC_SCHOLAR_API_KEY` 提升额度。
2. **arXiv 无法连接（read operation timed out）**：本机网络访问 `export.arxiv.org` / `arxiv.org` 读超时。

### 1.2 根因（先查真实失败原因，而非隐藏报错）

| 编号 | 真实原因 | 性质 | 处理方向 |
| --- | --- | --- | --- |
| R1 | Semantic Scholar 匿名配额不足，返回 429；属于服务商侧限流，不是代码参数错误 | 外部限流 | 遵守 `Retry-After` 退避重试一次；识别可重试错误；单源失败隔离，不中断整任务；保留可选 API Key 提额入口 |
| R2 | arXiv 在当前网络环境下连接/读取超时；预印本源对中文体育主题本就覆盖有限 | 网络不可达 + 主题覆盖弱 | 独立超时配置；网络错误一次重试；失败后由其他源接管 |
| R3 | 旧链路为 SS → arXiv 的两源串行回退，缺少稳定的备用学术库；两源同时受限时整体返回空 | 架构单点 | 增量接入 OpenAlex、Crossref、PubMed 三源，形成五源编排 |
| R4 | 缺少统一的状态、耗时、失败原因记录；单源失败与「无结果」「全部失败」混在一起，前端无法如实展示 | 可观测性不足 | 每源生成 `SourceReport`，汇总 `RetrievalReport`，前端看板如实呈现 |
| R5 | 旧链路对跨源元数据缺少统一校验与去重，无法区分真实、不完整、不可核验记录 | 数据质量控制不足 | 统一 `CandidatePaper` 模型 + 标题/DOI/字段校验 + 三级分级 + 多级去重 |

### 1.3 明确不属于故障的部分

- 大模型综述、PDF 入库、BM25/Chroma 检索、知识图谱派生、学习测评与问答链路本身可运行；本轮不重写这些模块，只在检索结果导入与派生失效处做增量衔接。
- 429 与超时是外部服务/网络状态，**不通过更换 IP、代理轮换等方式规避**；系统只做合规的退避、重试与跨源切换。

## 三、多数据源调用流程

### 3.1 数据源顺序

固定调度顺序（`SOURCE_ORDER`）：

```
Semantic Scholar → arXiv → OpenAlex → Crossref → PubMed
```

某一源成功或失败都不阻断后续源；最终结果跨源合并、去重、分级后统一返回。

### 3.2 端到端流程

```
用户在「智能文献研究」页输入研究问题
        │
        ▼
LiteratureResearchAgent.run(question, limit)
        │
        ├─ 已配置大模型：Function Calling 优化检索式后检索
        └─ 未配置 Key：规则清理检索式（不臆造英文术语）
        │
        ▼
MultiSourceRetriever.search(query, limit, date_from, date_to)
        │
        ├─ expand_query：体育科研中英同义词扩展（不替换原始检索词）
        ├─ 进程内缓存：相同「源+检索式+条数+日期范围」未过期则直接复用
        │
        ▼
按顺序调度五个适配器（统一签名 (query, limit, date_from, date_to, config)）
        │
        ├─ 每个源：限速等待 → 发起请求 → 错误码识别 → 退避重试/隔离
        ├─ 适配器输出统一 CandidatePaper
        │
        ▼
编排层汇总：标题非空过滤 → quality_tier 三级分级 → deduplicate 多级合并
        │
        ▼
RetrievalReport：候选 + 各源 SourceReport + 计数（原始/去重/DOI/摘要/全文/全失败/告警）
        │
        ▼
前端看板：主题、各源状态、成功数量、去重数量、可核验 DOI、题录/摘要/全文状态、失败原因与建议
        │
        ▼
用户勾选候选 → import_candidates 写入专题论文库（相关性判断兜底）
        │
        ▼
schedule_for_domain：标记专题待更新，后台增量重算分歧分析 / 知识图谱 / 综述 / 测评 / 问答
```

### 3.3 适配器与数据源对应

| 数据源 | 适配器 | 元数据来源 | 摘要/全文边界 |
| --- | --- | --- | --- |
| Semantic Scholar | `_adapt_semantic_scholar` | SS 公开图接口题录、摘要、开放 PDF 链接 | 仅来源提供的摘要；开放链接才标注全文 |
| arXiv | `_adapt_arxiv` | arXiv Atom 预印本题录 | 预印本摘要；不抓取全文 |
| OpenAlex | `_adapt_openalex`（复用 collectors） | OA 题录、OA 链接 | 元数据 + 开放链接 |
| Crossref | `_adapt_crossref`（复用 collectors） | DOI、标题、作者、期刊、年份 | 题录为主，不冒充摘要 |
| PubMed | `_adapt_pubmed` | NCBI E-utilities esearch + esummary 题录 | **仅题录**，不二次抓取摘要，避免题录冒充摘要/全文 |

### 3.4 中英文与同义词处理

- 主检索词始终保留并置于扩展首位；同义词仅用于补充检索式与相关性提示。
- 内置体育科研常用中英同义词组：体育锻炼/身体活动/运动干预、体质健康/体能/身体素质、大学生/高校学生、青少年/儿童、运动生理学/有氧能力/心肺耐力、运动表现/训练效果等。
- PubMed 为英文医学库：检索式先经 `expand_query` 提取英文同义词组合检索；无英文词时才使用原词，避免中文词被 E-utilities 退化为近期泛文献。

## 四、HTTP 429 与请求失败处理机制

### 4.1 错误分类

| 类别 | 状态码 | 处理 |
| --- | --- | --- |
| 可重试 | `429`、`403`、`500`、`502`、`503`、`504` | 退避后按最大重试次数重试；仍失败则隔离到该源 `SourceReport` |
| 不可重试 | `400`、`401`、`404`、`410`、`422` | 视为确定性错误，不重试，直接记录失败原因 |
| 网络/解析异常 | `URLError`、`TimeoutError`、`OSError`、`JSONDecodeError` | 标记可重试，按退避策略重试后隔离 |

### 4.2 退避、限速与超时

1. **Retry-After 优先**：遇到 429 优先读取响应头 `Retry-After`；缺失时回退到指数退避；延迟被限制在配置上限内。
2. **指数退避 + 随机抖动**：`base * 2^attempt`，再叠加 `0 ~ base` 的随机抖动，封顶 `max_backoff`，避免多进程/多请求同步重试造成再次集中打满。
3. **最大重试次数**：除 SS/arXiv（工具内部已自带限流/网络重试）外，其余源按 `RETRIEVAL_MAX_RETRIES` 重试；SS/arXiv 在编排层不再叠加外层重试，避免超时被放大。
4. **限速间隔**：相邻请求之间保证最小间隔 `RETRIEVAL_REQUEST_INTERVAL_SECONDS`，避免短时间集中打满数据源。
5. **连接/读取超时**：统一使用 `RETRIEVAL_TIMEOUT_SECONDS`；SS、arXiv 保留各自独立超时配置。
6. **本地缓存**：按「源 + 检索式 + 条数 + 日期范围」做进程内 TTL 缓存，相同检索式不重复请求；TTL 由 `RETRIEVAL_CACHE_TTL_SECONDS` 控制，设为 0 可关闭。
7. **状态记录**：每个源记录状态（success/empty/failed/disabled）、请求数、返回数、耗时（ms）、HTTP 状态、失败原因、是否可重试、尝试次数、面向用户的重试建议。
8. **单源隔离**：任一源抛异常只影响自身报告，不中断其他源；全部源失败时 `all_failed=True`，前端明确提示，不生成综述或虚构引用。

### 4.3 合规边界

- API Key 统一从 `.env` / 环境变量读取，代码中不写死任何密钥。
- 不更换 IP、不使用代理轮换、不绕过付费墙；只读取公开元数据与开放获取链接。

## 五、数据真实性与质量控制机制

### 5.1 统一数据模型

所有源适配器输出统一的 `CandidatePaper`：`candidate_id, title, authors, year, journal, doi, source_url, abstract, keywords, source, pdf_url, is_open_access`，供既有导入链路直接消费。

### 5.2 校验规则

| 规则 | 实现 |
| --- | --- |
| 标题非空 | 标题去空白后为空的记录直接在去重/汇总阶段过滤 |
| 关键字段尽量完整 | 作者、年份、期刊、摘要、关键词逐字段保留；缺失字段保留为空并在分级中体现，不补造 |
| DOI 格式校验 | `normalize_doi` 去协议前缀/首尾标点/转小写；`is_valid_doi` 校验 `10.后缀/标识` 基本形态 |
| DOI 优先去重 | 有 DOI 时按规范化 DOI 作为合并键 |
| 无 DOI 辅助去重 | 无 DOI 时按规范化题名（忽略全半角、大小写、空白、标点）+ 年份合并 |
| 跨源合并补全 | 合并重复记录时用字段更完整的一条补齐缺失项，保留信息更全的主体 |

### 5.3 三级质量分级（`quality_tier`）

| 级别 | 判定条件 | 前端/导入含义 |
| --- | --- | --- |
| `verified` | DOI 格式有效，且作者、年份齐全 | 可核验记录，优先展示与导入 |
| `incomplete` | 题录可读，但缺 DOI 或缺作者/年份等关键元数据 | 需人工补全核验 |
| `unverifiable` | 无 DOI 且题名残缺或年份缺失，无法可靠核验 | 不建议作为结论依据 |

### 5.4 真实性红线（代码内强制约束）

- 不伪造论文、DOI、作者、期刊、引用次数；引用次数字段不参与编造。
- 不把检索摘要冒充论文全文；未获取全文时明确标注「仅题录」或「含摘要」「未获取全文」。
- 论文卡片分别标注：DOI 是否可核验、内容层级（含摘要 / 仅题录）、访问层级（开放全文 / 未获取全文）。
- PubMed 题录不填摘要；Crossref/OpenAlex 仅在来源提供摘要时保留摘要。
- 全部源失败时：综述只输出「证据不足、未生成综述或虚构引用」的状态说明，不生成学术结论、不生成 GB/T 7714 引用。

> 说明：看板中的「可核验 DOI 数量」统计的是 **DOI 格式有效** 的记录数，不等同于主题相关；主题相关性由导入环节的相关性判断进一步把关，边缘主题条目会被跳过或提示人工核验。

## 八、本地启动与使用说明

### 8.1 环境准备

- Windows 10/11（开发机）、Python 3.11/3.12；依赖见 `requirements.txt`。

```powershell
cd "<解压后的项目根目录>"
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

### 8.2 配置

按需在 `.env` 填入大模型与可选检索密钥；不填也能运行本地文献库、规则检索与规则整理。

### 8.3 启动应用

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
```

默认访问 `http://localhost:8501`。

### 8.4 使用流程

1. 进入「**智能文献研究**」页面，输入研究主题（支持中文/英文关键词）。
2. 查看顶部多源看板：当前主题、各数据源名称与状态、成功数量、去重后数量、可核验 DOI 数、题录/摘要/全文状态、失败原因与重试建议、数据源切换情况。
3. 浏览论文卡片：核对 DOI、作者、年份、期刊、摘要与开放链接；无全文的记录明确标注「仅题录/未获取全文」。
4. 勾选需要纳入专题库的论文，点击「**导入所选到专题论文库**」；不相关条目会被相关性判断跳过并在明细中说明。
5. 导入完成后系统自动标记专题待更新，后台增量重算分歧分析、知识图谱、综述与学习测评；无需每次重处理全部论文。
6. 在论文库中可对已导入论文执行查看、软删（可恢复）、永久删除；删除后相关分析缓存、明确引用该论文的试题与答题记录会被同步失效/清理，知识图谱基于剩余论文重算。
7. 若全部数据源失败，页面会明确提示「未获得可核验论文，未生成综述或引用」，不会出现失败却显示成功，也不会生成虚假综述。

### 8.5 运行测试

```powershell
.\.venv\Scripts\python.exe -m pytest tests -q --basetemp .pytest-tmp-run
```

仅跑本轮新增检索编排测试：

```powershell
.\.venv\Scripts\python.exe -m pytest tests\test_multi_source_retrieval.py -q --basetemp .pytest-tmp-run
```

### 8.6 能力边界与已知限制

- 检索仅覆盖公开学术元数据与开放获取链接，不爬取付费墙与知网；正式引用前必须打开原文核验卷、期、页码与文献类型。
- 缓存为进程内 TTL 缓存，不落盘；应用重启后缓存清空。
- PubMed 匿名调用有频率限制，可配置 `PUBMED_API_KEY` 提额；题录不含摘要正文。
- 本轮未改动既有数据库结构与已有论文数据；专题库、旧库与用户上传 PDF 的隔离边界保持不变。
